# NoxVoid Software — Official Website & Markdown Blog

Official website for **NoxVoid Software** (`noxvoid.github.io`), featuring all 5 products, dynamic Markdown-powered blog, automated sitemap/robots generation, and GitHub Actions CI/CD deployment.

---

## ✍️ How to write a new blog post in Markdown

1. Add a new `.md` file in `content/blog/`, for example `my-new-post.md`:
   ```markdown
   ---
   title: "Your Post Title"
   description: "Short summary of the post for SEO and preview cards."
   date: "2026-11-20"
   category: "Engineering"
   readTime: "4 min read"
   slug: "my-new-post"
   ---

   Your article content in standard Markdown...
   ```
2. Commit and push:
   ```bash
   git add .
   git commit -m "feat: new article"
   git push
   ```
3. **GitHub Actions automatically:**
   - Converts Markdown to responsive HTML with OpenGraph and Schema.org JSON-LD.
   - Updates `blog.html` with the new article card.
   - Updates `sitemap.xml` with the new URL, date, and priority.
   - Updates `robots.txt`.
   - Deploys the site live to GitHub Pages in ~30 seconds!

## 🧩 Jira app pages & policies (generated)

The Jira app pages and their legal pages are generated by `npm run build` (`scripts/lib/pages.js`, shared chrome in `scripts/lib/layout.js`). Generated files (these pages, `blog/`, `blog.html`, `sitemap.xml`, `robots.txt`) are git-ignored: GitHub Actions builds and deploys them on every push to `main` (Pages source: **GitHub Actions**). Run `npm run build` to preview them locally, and change the sources, not the HTML.

| Source | Generates |
|---|---|
| `content/apps/<slug>.json` | the product page (`file` in the JSON, e.g. `domainguard-jira.html`) |
| `content/legal/<slug>/privacy.md`, `terms.md`, `security.md` | `privacy-<slug>.html`, `terms-<slug>.html`, `security-<slug>.html` |
| `content/legal/_shared/<doc>/<name>.md` | sections shared by every app, included with `{{> terms/support}}` |

- Every product page has the same sections: hero (badges, lead, chips, Marketplace / Knowledge Base buttons), overview, 3 highlights, features, "How it works" steps, optional audience list, trust card, quickstart, and a specs sidebar. Vendor, Support and legal links are added automatically.
- JSON text fields accept inline Markdown (`**bold**`, `` `code` ``, `[link](url)`).
- In policies, write headings as `## Name`: the build numbers them (`## 3. Name`), including shared sections. Front matter holds `description` and `updated` (the "Last modified" date).
- To add an app: create `content/apps/<slug>.json` and the three policy files, then add the new URLs to `staticPages` in `scripts/build.js` for the sitemap.

## 🛠 Local Development & Testing

```bash
# Install dependencies
npm install

# Build Markdown articles, blog index, sitemap.xml & robots.txt
npm run build

# Preview locally
python3 -m http.server 8085
```
Open [http://localhost:8085](http://localhost:8085) to view changes.

## 🚀 Initial GitHub Setup

1. Create a public repository on GitHub: `https://github.com/NoxVoidSoftware/NoxVoidSoftware.github.io` (or `noxvoid.github.io`).
2. Go to **Settings** &rarr; **Pages** &rarr; **Build and deployment**.
3. Under **Source**, select **GitHub Actions** (the official modern GitHub Pages workflow).
4. Push your code:
   ```bash
   git init
   git add .
   git commit -m "feat: initial commit with markdown blog and github actions"
   git branch -M main
   git remote add origin https://github.com/NoxVoidSoftware/NoxVoidSoftware.github.io.git
   git push -u origin main
   ```
5. GitHub Actions will build and deploy your site automatically!
